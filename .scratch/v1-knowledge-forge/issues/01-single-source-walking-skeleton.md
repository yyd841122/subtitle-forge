# 01 — 单 Source walking skeleton：端到端替身接缝

**What to build:** 一个含受控知识内容的 ASS Source，经确定性提炼替身与审查替身走完完整路径：解析为 Corpus→Source→Segment 模型 → 提炼出带 Source Reference 的知识单元 → 审查替身判定通过 → 进入可信发布集（Trusted Set）→ 产出缺口报告（本次为空，结构成立）→ 产出运行摘要（该 Source 及其知识单元均有实体状态）。这是全部验收条件（A1–A22）共用的端到端测试接缝——按认知角色（提炼/推理审计/覆盖审计）独立注入确定性替身的机制在本票落地，后续所有票在此接缝上以产品级断言验收。

单一 Source、单一运行请求形态即可；批处理、多 Source、指定范围等扩展能力属于 02 票。本票不是纯技术基础设施票——完成的判定就是"一个 Source 的知识单元走完 从提炼到可信发布 的完整可观察路径"。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 单 Source 端到端：ASS 输入 → 解析 → 提炼替身产出知识单元（带 Source Reference）→ 审查替身判定"通过"→ 该单元出现在可信发布集中，运行后可指认
- [ ] Source Reference 由"原文文本片段 + 定位信息"构成；V1 的 ASS 实例使用时间区间作为定位信息，但定位信息的表达不把时间区间设为必填——结构上保留非时间定位类型（如文本位置）的表达空间（R1.4 未来兼容约束，Q26）
- [ ] 知识单元类型不限于 Claim——方法、解释、案例、论证、结论等均可在资产中表达（R2.2）
- [ ] 缺口报告作为一等产物产生（本次运行无异常时内容为空，结构完整：人可读 + 机器可解析）
- [ ] 运行摘要：该 Source 有实体状态（成功），每个知识单元有实体状态（通过/拒绝/待复核/失败枚举可表达，本次为通过）
- [ ] 确定性替身可按认知角色（提炼 / 推理审计 / 覆盖审计）独立注入并分别设定行为；替身注入是测试输入的一部分（Testing Decisions）
- [ ] 断言只针对外部产物（可信发布集内容、缺口报告、运行摘要），不断言内部结构（阶段函数签名、中间产物格式、目录布局）
- [ ] 忠实层/审查层、基础层/衍生层的概念边界在资产组织中成立（忠实知识与系统判断分开存放；每 Source 资产独立成立），最小形态即可（R2.5、R2.6 的结构前提）

> 实现决策（本票裁定并记录 ADR）：语言与运行时选型（Open Impl 18）；CLI 最小入口形态（Open Impl 1，仅当前运行请求所需）；知识单元 schema 与 Source Reference 的 locator 结构（Open Impl 15——注意 locator 不得锁死时间区间必填）；替身注入机制（Open Impl 12）；规范源格式的初始形态（Open Impl 7——可被 15 票正式验收修正）。
