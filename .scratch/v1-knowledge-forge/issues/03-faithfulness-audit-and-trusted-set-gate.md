# 03 — 忠实性审计与可信发布集门

**What to build:** 端到端运行后，知识单元的逐字引用经程序比对与原文核实，只有审计"通过"的知识单元进入可信发布集；"引用不存在于原文"的单元被拦在门外并在缺口报告中留下"审计拒绝"条目。知识单元级实体状态枚举（通过/拒绝/待复核/失败）在外部产物中落地；无有效 Source Reference 的单元同样不得进入可信发布集，且有显性下落。

**Blocked by:** 01 — 单 Source walking skeleton（审计门作用在骨架建立的资产与替身接缝上；不依赖 02 的批处理能力）。

**Status:** ready-for-agent

- [ ] A1 审计门：注入"引用不存在于原文"的知识单元（提炼替身），运行后该单元不出现于可信发布集；缺口报告含"审计拒绝"条目并指向该单元
- [ ] A17 引用不变量：注入无有效 Source Reference 的知识单元，该单元不进入可信发布集，且在运行摘要/缺口报告中有显性下落（归入哪类 Gap Category 由实现裁定）
- [ ] 忠实性比对可程序化执行（具体算法——精确/规范化/模糊匹配——由实现裁定，Open Impl 10）
- [ ] 知识单元级实体状态枚举（通过/拒绝/待复核/失败）在外部产物中可观察
- [ ] 可信发布集成员资格只由知识单元的审计结果（"通过"）决定；拒绝只发生在知识单元级（R3.5、R2.4）
- [ ] 忠实性审计含纯程序比对部分，不经由生成同一内容的替身自评（R3.1、生成与审查分离的最小实现）
- [ ] 被拒知识单元的物理下落（中间产物、隔离目录或其他）在本票裁定（Open Impl 6 之失败单元部分、ADR-0003）；其存在、被拒原因与关联 Source 在缺口报告显性记录、可追溯

> 实现决策（本票裁定并记录 ADR）：忠实性比对算法（Open Impl 10）；无引用单元的 Gap Category 归属（R2.4 留白）；被拒内容的物理存放方式（Open Impl 6 之失败单元部分，ADR-0003）。
