# 05 — 最小资产版本信封

**What to build:** 建立资产版本（Asset Version）的最小语义：每次运行的产物归属于一个可指认的资产版本；"当前资产版本内的全量实体"这一对账作用域可观察。后续对账（06）、增量重算与幂等（10）、可移植与唯一规范源（15）都以本票建立的版本语义为前提，避免在版本化之前固化 Run Summary 或 canonical 布局后返工。

**只建语义，不在 ticket plan 中预先指定机制**：版本标识的具体实现（版本字段形态、递增方式、存放位置）与输入身份识别机制（哈希算法等）都是 Open Implementation Decisions，本票不锁定——实现时仍须选择某种具体表示，但不由本票预定。完成的判定是外部可观察行为：任意一次运行后，可以指认每个产物属于哪个资产版本；两次运行以不同标准运行时，产物归属的版本可区分。

**Blocked by:** 01 — 单 Source walking skeleton（版本信封作用在骨架产物上）。可与 02/03/04 并行。

**Status:** ready-for-agent

- [ ] 任意一次运行后，可信发布集、缺口报告、运行摘要均可指认其归属的资产版本（R5.4"区分资产版本"的最小语义）
- [ ] 以不同提炼/审计标准（替身行为或规则配置变化）运行两次：两次产物归属的版本可区分，可同时指认"这是哪一版标准的产物"（A20 的最小语义半；A20 的"同版本内无新旧标准混杂"完整验收由 10 票联合完成）
- [ ] 对账作用域可观察：运行摘要能区分"当前资产版本内的全量实体"与"本次运行实际处理的实体"（为 06 票的 A3 对账提供版本作用域；跳过引用既有产出的分支由 10 票联合补全）
- [ ] 不锁定实现：版本标识的实现方式（字段形态/递增机制/存放位置，Open Impl 3）与输入变化识别机制（Open Impl 2）保持为实现决策，断言只针对外部可指认性

> 实现决策（本票裁定并记录 ADR）：资产版本标识的实现形态（Open Impl 3）；运行请求如何声明/继承版本（规则配置与版本的对应方式）。
