# 10 — 版本化再生：幂等、变更检测、版本区分

**What to build:** 系统能识别输入是否变化、在版本信封（05 票）之上实现增量与重跑语义。同一 Corpus、同一资产版本连续运行两次，第二次跳过未变化且已成功的 Source（在运行摘要中可辨、引用既有产出），可信发布集与缺口报告内容不变、无新旧混杂；修改某个 Source 后重跑，仅该 Source 被重新处理。失败结果不被跳过逻辑误认为已完成。

**Blocked by:** 06 — 全量对账与缺口报告一等资产（幂等与跳过语义需要在运行摘要中可观察；含 02/04/05 的传递依赖）。

**Status:** ready-for-agent

- [ ] A5 同版本幂等：同一 Corpus、同一资产版本连续运行两次，第二次跳过未变化且已成功的 Source（运行摘要中可辨、引用既有产出——至此与 06 票联合完成 A3 的跳过分支）；可信发布集与缺口报告内容不变（允许时间戳类运行元数据不同）；无新旧混杂
- [ ] A6 输入变化检测：修改一个 Source 的内容后重跑，仅该 Source 被重新处理，其余 Source 保持原产出
- [ ] A20 版本可区分（完整验收）：修改提炼或审计标准后重跑，新资产版本与旧版本可区分（可同时指认"这是哪一版标准的产物"），同版本内无新旧标准混杂（最小语义半在 05 票）
- [ ] 失败结果不被误认为已完成——跳过判定不能只看"产物存在"（R5.4、ADR-0004）：受控注入一次失败的运行后重跑，失败 Source 被重新处理而非跳过
- [ ] 半成品不被视为有效产物：受控中断后重跑，未完成的中间结果不进入可信发布集，恢复后最终产出无新旧混杂（行为约束：半成品不可复用、不可被当作有效结果——不要求物理上不存在半写内容）
- [ ] 用户不直接修改生成资产；规则变化通过新版本重新生成（R5.4）

> 实现决策（本票裁定并记录 ADR）：输入变化识别机制——哈希算法与比对粒度（Open Impl 2）；跳过判定机制——四要素（输入未变+版本一致+阶段成功+产物有效）的校验方式（Open Impl 4）；写入的完整性保障机制（Open Impl 5，不预设具体技术）——验收点是外部行为：半成品不可复用、恢复后无混杂。
