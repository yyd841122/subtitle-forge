# 0003 — 审计不过不进可信发布集；可信指标与覆盖指标成对存在

已接受（2026-09-01，grilling R3 确认；2026-09-01 审查修订：删除物理存储布局与错误类别的未确认细节，恢复指标的抽象表述）。

质量优先级为 可信 > 信息完整性，红线必须同时服务两者。**决策：可信性拒绝只发生在知识单元级**（不是整份 Source 作废），审计不通过的知识单元不得进入可信发布集；失败、拒绝与覆盖缺口必须显性保留（缺口报告为一等资产）。全局性错误允许中止整批运行——哪些错误属于全局性、中止的判定标准属于实现决策。

一个被明确堵住的漏洞：**可信性指标必须与知识覆盖指标成对存在**——只看审计通过，系统可以通过少提炼内容获得高质量分（"少做少错"）。配套要求输入-输出对账：所有 Source 和知识单元都有明确下落（实体状态见 PRODUCT.md"实体状态与缺口类别"），不允许静默消失。

被拒内容的逻辑归属：不进入可信发布集，但必须可追溯（其存在、被拒原因与关联 Source 在缺口报告中显性记录）。其物理存放方式（中间产物、隔离目录或其他）属于实现决策。

后果：最坏情况是"资产不完整且缺口可见"；审计门是进入可信发布集的必要条件而非真实性的绝对保证——审计器自身的漏检与误杀需在运行中通过人工抽查校准。具体阈值与指标形式待真实运行数据校准。
