# 0004 — 重算语义：版本化再生，用户不手改生成资产

已接受（2026-09-01，grilling R3 确认；2026-09-01 审查修订：删除未经拍板的机制性结论——override 触发条件、被否决机制清单等，只保留已确认的产品原则）。

批量提炼必然反复发生"提示词改进 / 输入更新 / 阶段失败"，需要明确的增量与重跑语义。**决策（产品原则，实现机制不锁定）**：用户不直接修改生成资产，规则变化通过新版本重新生成。V1 必须能：

- 识别输入是否发生变化；
- 区分不同提炼/审计标准生成的资产版本；
- 同一版本重跑不留新旧结果混杂；
- 已成功且未发生变化的结果可以跳过；
- 失败结果不被误认为已完成（跳过判定不能只看"产物存在"）。

如何实现（哈希方式、版本字段设计、原子写入、缓存策略等）属于实现决策。人工 override/annotation 机制与更重的版本管理体系在 V1 未引入——这属于本轮范围决定，不是对未来架构的否决；何时引入由实现阶段的实际需要决定。
