# 0007 — 重新拆票：废弃旧 Ticket 02–15，按 Implementation Plan v2.2 实例化正式票 02–29

已接受（2026-09-02，Claude + Codex 三轮审查闭环后 materialize；Codex 最终 verdict READY TO MATERIALIZE）。

## 背景：为什么废弃旧 Ticket 02–15

旧 15 票计划（`.scratch/v1-knowledge-forge/issues/01–15`）在实际进入实现阶段后暴露
implementation-readiness 不足：

- **fresh agent 无法自含开工**：理解一张票的边界需要读取多张后续票（尤其旧 02
  混合批处理与运行范围等多种职责，边界互锁）；
- **单票职责过大**：多张票绑定多个产品增量，超出单 agent session 可靠完成的范围；
- **验收与依赖不自含**：部分验收依赖未来票才存在的机制/语义，依赖图主要靠编号
  顺序成立，而非真实依赖。

决策：不做旧计划修补，从 Spec（A1–A22 / R1–R7）与 Ticket 01 代码现状重新推导。
旧票保留原始内容归档于 `.scratch/v1-knowledge-forge/issues/archive-v1/`，仅作历史
留存，不再是任何实现、审查或规划的事实来源。

## 为什么采用 v2.2

新计划（`.scratch/v1-knowledge-forge/plan-v2-draft.md`，v2.2）经三轮 Claude 修订 +
Codex focused review 闭环（同一 Codex thread `01a060a5-8a73-7fb1-a173-fbc74ca661e7`：
第一轮 NEEDS REVISION（11 blocking）→ v2.1 → 第二轮 6 条新 blocking（全为依赖
声明问题）→ v2.2 → 第三轮 0 blocking、READY TO MATERIALIZE）。拆票原则：

- 每票**一个可观察产品增量**，验收全部落在端到端接缝的外部产物上（Testing
  Decisions：唯一测试接缝 = 端到端管线含运行请求）；
- **fresh-agent self-contained**：每票带「明确不含 + 触界行为（fail loud）」与自含
  词汇，实现不需读取任何后续票；
- **单 session 可完成**：原规模风险票已实际拆分（11a/11b、13a/13b、14a/14b、
  22a/22b、23a/23b/23c）；
- **确定性验收**：替身脚本化 fixture、tripwire、确定性计量；真实模型票（27–29）
  不承担任何确定性产品验收（A13 的确定性验收在 08）；
- **真实 dependency graph**：硬依赖图为唯一顺序事实，无环、与票卡声明双向一致，
  票号不承担依赖语义。

## Ticket 01 为什么不变

Ticket 01（单 Source walking skeleton）已完成并通过独立复审（Codex 0 blocking），
是稳定基线；其实现决策已由 ADR-0006 固化。重拆只针对 01 之后的计划，不动其实现、
测试与票面。

## 本 ADR 的边界

本 ADR 只记录**规划与拆票决策**，不锁定《Open Implementation Decisions》中任何
How 的具体选择；各票的「票内裁定」在实施时落 ADR 或票面。PRODUCT / CONTEXT /
Spec / ADR-0001–0006 / Ticket 01 均未因本 ADR 改动。

## 备择方案

- **修补旧 15 票计划**：职责边界已互锁，修补成本高于重拆，且无法恢复 fresh-agent
  自含性——不取。
- **更少、更大的票以减少管理开销**：与「单 session 可靠完成」直接冲突，第一轮
  审查已证伪——不取。
- **保留草案混合编号（11a/11b…）作为正式票号**：可行但引用易错、排序不显；
  连续编号 + 本映射表以极低成本换取更稳的引用——取现方案。
