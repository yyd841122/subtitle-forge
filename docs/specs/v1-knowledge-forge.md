# Subtitle Forge V1 — 软件规格

> 状态：**草案，待用户确认**。事实来源：`docs/PRODUCT.md`、`CONTEXT.md`、`docs/adr/0001–0005`。本文档不新增任何未经确认的产品目标；凡文档未覆盖且无法形成可执行规格之处，集中列于"规格级未决冲突"，不自行猜测。

## Problem Statement

用户手里有百集级的知识型字幕与转写文本（课程、讲座、访谈，以 ASS 字幕为主，中文为主）。这些内容以线性口语形态存在：知识埋在时间轴里，无法检索、无法引用、无法核对其中的断言是否真出自原文，也无法作为进一步加工（RAG 问答、写作、二次整理）的可靠原料。人工逐集做笔记不可行，而简单的"喂给 LLM 出摘要"无法保证忠实（不夹带原文不存在的信息）、无法保证不遗漏重要知识，也没有任何机制让用户核验这两点。

## Solution

Subtitle Forge 是一个单机、本地运行的阶段化批量提炼系统：用户把一批 Source（一个 Corpus）交给它，系统将每个 Source 独立提炼成带来源引用的分层知识资产——知识单元（Knowledge Unit，含声明 Claim，也含方法/解释/案例/论证/结论等）聚合为要点/主题/概要（Aggregate Knowledge）。提炼与审计分离：只有审计通过的知识单元进入可信发布集（Trusted Set）；被拒、失败、覆盖存疑与警告全部显性记录在缺口报告（Gap Report）中，所有 Source 与知识单元都有明确下落。资产为可移植的文件形态，人与 AI 都是一级消费者；跨 Source 关系与检索结构是可整体重算的衍生层。用户可以分阶段重跑、按 Source 重跑，规则改进后通过新版本重新生成，不直接手改生成资产。

## User Stories

**输入与语料组织**

1. 作为唯一用户，我想把一批 .ass 字幕文件组成一个 Corpus 交给系统，以便一次性批量提炼而不是逐集手工处理。
2. 作为唯一用户，我想让系统把每个输入识别为一个 Source（一集课程、一场访谈、一份转写），以便每个 Source 独立处理、独立追溯、独立重跑。
3. 作为唯一用户，我想让系统在 Source 内部识别出可定位的 Segment，以便知识单元的来源引用能锚定到原文的具体位置。
4. 作为唯一用户，我想让系统容忍字幕中常见的噪声（口头填充、重复、转写错误），以便提炼不被低质量片段打断，也不把噪声当知识。

**提炼与知识资产**

5. 作为唯一用户，我想让系统把每个 Source 提炼成分层的知识资产（知识单元 → 要点/主题 → 概要），以便不同粒度的消费都能满足。
6. 作为唯一用户，我想让知识单元不局限于 Claim（断言），也包括方法、解释、案例、论证、结论，以便过程性知识不被强行碎片化。
7. 作为唯一用户，我想让每个重要知识单元都带来源引用（Source Reference：原文文本片段 + 时间区间或文本位置），以便我核对任何一条知识确实出自原文。
8. 作为唯一用户，我想让时间戳缺失的转写文本也能用文本位置完成溯源，以便系统不依赖特定输入格式。
9. 作为唯一用户，我想让主题摘要、全篇概要作为 Aggregate Knowledge 存在并可单独接受质量审查，以便宏观层与微观层不混用同一审计尺度。

**可信审查**

10. 作为唯一用户，我想让系统对每个知识单元做忠实性审计（逐字引用真实存在于原文、可程序比对），以便机器先拦住最直接的造假。
11. 作为唯一用户，我想让系统对知识单元做推理审计（断言没有超出引用的支持范围），以便拦住"引用真实存在但断言是脑补"的漏洞。
12. 作为唯一用户，我想让提炼与审计作为两个独立认知环节存在，以便审计不是自我盖章。
13. 作为唯一用户，我想让审计不通过的知识单元被拒绝且不进入可信发布集，以便最坏情况是资产不完整，而不是资产不可信。
14. 作为唯一用户，我想让审查层对可疑内容（疑似口误、与常识冲突）产生审查注记（Review Note）而不是修改忠实层内容，以便"原文说的"与"系统认为的"永远可区分。
15. 作为唯一用户，我想让 Review Note 明确标注为系统判断并与忠实层分离存放，以便我永远知道哪句话是原文、哪句是系统的意见。

**完整性与缺口**

16. 作为唯一用户，我想让系统以知识覆盖（核心概念、方法、论点、解释、重要案例、条件、结论）衡量完整性，以便寒暄和口头填充不被强行塞进资产。
17. 作为唯一用户，我想让缺口报告作为一等资产存在（人和 AI 都能读），以便没有任何 Source 或知识单元静默消失。
18. 作为唯一用户，我想让缺口报告区分执行失败、审计拒绝、覆盖存疑、警告四类缺口，以便我知道每个缺口的性质和该采取的动作。
19. 作为唯一用户，我想让系统的可信指标与知识覆盖指标成对出现，以便"少提炼、少出错"的保守策略在指标上无利可图。

**运行、重算与版本**

20. 作为唯一用户，我想一次运行完成整个 Corpus 的完整流程，以便不需要手工串联各阶段。
21. 作为唯一用户，我想在某个阶段失败或规则改变时只重跑受影响的部分，以便迭代不用付全量成本。
22. 作为唯一用户，我想让中间结果支持恢复和继续执行，以便中断不丢已完成的工作。
23. 作为唯一用户，我想让系统识别输入是否发生变化，以便字幕更新后只重处理变化的 Source。
24. 作为唯一用户，我想让系统区分不同提炼/审计标准生成的资产版本，以便审计结论与资产版本可以对应。
25. 作为唯一用户，我想让同一版本重跑不留下新旧结果混杂，以便不会出现"半新半旧"的资产。
26. 作为唯一用户，我想让已成功且未变化的 Source 被跳过，以便重跑不重复花钱。
27. 作为唯一用户，我想让失败结果不被误认为已完成（跳过判定不能只看产物存在），以便坏结果不会被静默复用。
28. 作为唯一用户，我想让全局性错误中止整批运行，以便明知环境已坏时不产生一批不可信的产物。
29. 作为唯一用户，我承诺不直接修改生成资产、通过新版本重新生成，以便资产永远可由规则重建。

**人工抽查与反馈**

30. 作为唯一用户，我想按风险驱动抽查（失败项、被拒项、低可信项、覆盖存疑项、随机已通过项、高价值 Source），以便有限时间花在最可能有问题的地方。
31. 作为唯一用户，我想把抽查中发现的系统性问题转化为规则/提示词修改后重跑，以便质量反馈沉淀为可重复的标准。

**成本与消费**

32. 作为唯一用户，我想让成本和耗时可观察、可比较、可控制，以便在质量优先的前提下管理开销。
33. 作为唯一用户，我想让系统不为了省钱而静默降低可信标准，以便可信发布集的准入门槛永远一致。
34. 作为唯一用户，我想得到可移植、可独立保存的文件形态资产，以便资产不依赖本系统存活。
35. 作为唯一用户，我想让索引与缓存可删除、可重新生成，以便清理它们永不损失知识。
36. 作为唯一用户，我想让人和机器都是资产的一级消费者（人直接可读、机器可程序化解析），以便阅读、RAG、二次加工共用同一份规范资产。
37. 作为唯一用户，我想让资产按 Source 组织且存在唯一规范数据源，以便多个表示之间不会双向漂移。
38. 作为唯一用户，我想让跨 Source 的关联、重复、深化、矛盾作为可整体重算的衍生层存在，以便衍生层坏了可以重算而不污染基础层。

## V1 产品要求（MUST）

> 措辞约定：**必须**=不满足即验收失败；**不得**=出现即验收失败；**应该**=默认要求，偏离需在实现中记录理由。

### R1 语料与输入

- **R1.1** 系统**必须**以 Corpus 为批处理单位、以 Source 为独立提炼单位、以 Segment 为引用锚定目标。
- **R1.2** V1 **必须**能处理 ASS 字幕作为 Source；其他格式的接入不得被架构性排除（解析层可扩展），但具体格式不在 V1 验收范围。
- **R1.3** 系统**必须**容忍常见噪声与转写错误：噪声**不得**导致整 Source 失败，也**不得**作为知识进入资产。
- **R1.4** 系统**不得**把产品设计锁定为只能处理中文。时间戳不是 Source Reference 成立的必要条件——这是**未来兼容约束**：V1 当前只验收带时间轴的真实输入；无时间轴 Source 未来应能通过其他定位方式（如文本位置）获得 Source Reference。V1 **不**把无时间轴输入纳入验收范围（Q26 裁决）。

### R2 知识资产

- **R2.1** 每个 Source 的资产**必须**为分层结构：知识单元层 + 聚合层（要点/主题/概要）。
- **R2.2** 知识单元**必须**是可独立引用、审计、接受、拒绝、待复核的基础语义产物单位；类型**不得**限于 Claim。
- **R2.3** 聚合知识（Aggregate Knowledge）**不得**与知识单元共用同一套单元级状态与通过率指标；聚合层**可以**单独接受质量审查。
- **R2.4** **无有效 Source Reference 的 Knowledge Unit 不得进入可信发布集，且必须有显性下落**（可观察、可对账；具体归入哪一种 Gap Category 属于实现决策）。Source Reference = 原文文本片段 + 定位信息。
- **R2.5** 忠实层与审查层**必须**分离：忠实层忠实表达来源内容；Review Note 属于系统判断，**必须**明确标注并与忠实层分离存放；系统**不得**因存疑修改忠实层内容。
- **R2.6** 基础层与衍生层**必须**分离：每个 Source 的基础层结果独立成立；跨 Source 关系属衍生层，可整体重算，**不得**反向污染基础层。
- **R2.7** V1 的衍生层交付程度（裁决 5）：**不要求**完整实现跨 Source 的概念归并、关系推理、矛盾检测等衍生知识能力；只要求基础层与衍生层边界明确、衍生层可重算原则被保留，避免未来被基础资产结构锁死。

### R3 可信审查

- **R3.1** V1 **必须**包含忠实性审计（引用真实存在、可程序比对）。
- **R3.2** V1 **必须**包含推理审计（知识表达不超出来源支持范围）。
- **R3.3** V1 **必须**包含知识覆盖审计，且其属于**独立审查环节**的职责：提炼阶段可产生覆盖自检信号，但生成者自评**不得**作为最终覆盖结论（裁决 3）。
- **R3.4** 提炼与审计**必须**作为两个独立认知环节存在（是否使用不同模型不是产品要求）。
- **R3.5** 审计不通过的知识单元**不得**进入可信发布集；拒绝只发生在知识单元级。
- **R3.6** Review Note 属于**审查层产物**：提炼阶段可以发现疑点，但正式 Review Note **必须**由审查环节确认并产出（裁决 4）。
- **R3.7** V1 **不要求**系统判断外部世界事实真伪（Review Note 表达存疑即可，不裁决真伪）。
- **R3.8** "低可信"**不是**独立状态或领域术语，只作为触发待复核或提高抽查优先级的风险信号（裁决 2）。

### R4 完整性与缺口

- **R4.1** 完整性以知识覆盖衡量（核心概念、方法、论点、解释、重要案例、条件、结论），**不得**以文本覆盖（逐段落入资产）为标准。
- **R4.2** 缺口报告**必须**是一等资产（人与 AI 均可读），至少区分四类缺口类别：执行失败、审计拒绝、覆盖存疑、警告。缺口报告只记录异常与缺口，不承担全量正常对账职责（裁决 6）。
- **R4.3** 输入-输出对账**必须**成立且由运行摘要（Run Summary）承载：对账作用域为**当前资产版本内的全量实体**（每个 Source 与每个知识单元都有明确下落/实体状态），本次运行实际处理的实体单独可辨；无静默消失（裁决 6 + 审查裁决）。
- **R4.4** 待复核（Needs Review）状态**必须**保持其严格含义：系统当前无法可靠判定该 Knowledge Unit 应通过还是拒绝、但存在足够理由需要人工或后续审查；它**不得**用作"低质量"的兜底状态或一般警告（裁决 1）。
- **R4.5** 可信性指标与知识覆盖指标**必须**成对存在（运行产出同时包含两者；只报其一即验收失败），使"少提炼、少出错"的保守策略在指标体系下无利可图（ADR-0003）。指标的具体形式待运行校准。
- **R4.6** 实体状态语义（不定义完整状态迁移图，只定义可观察语义；"拒绝、待复核、失败"三者不得混用）：
  - **Source 成功**：处理流程完整结束，所有 Knowledge Unit 均有明确、可解释的下落。存在被审计拒绝的 Knowledge Unit 本身不妨碍 Source 成功。
  - **Source 待复核**：存在尚未获得最终结论、需要后续人工或系统判断的问题，使 Source 尚不能视为完全 settled。
  - **Source 失败**：处理流程无法完整完成，无法形成符合规格要求的 Source 结果。
  - 重跑后实体状态以最新一次有效结果为准（同版本覆盖语义的自然延伸）；"跳过"不是实体状态，是运行行为——被跳过的 Source 在 Run Summary 中以引用既有产出的方式表达，不新增状态值。

### R5 运行、重算与版本

- **R5.1** 用户**必须**能一次运行完整流程，也能独立重跑关键阶段。
- **R5.2** 某阶段失败或规则改变时，**不得**要求整个 Corpus 从头执行。
- **R5.3** 中间结果**必须**支持恢复与继续执行。
- **R5.4** 系统**必须**能：识别输入变化；区分资产版本；同版本重跑不留新旧混杂；成功且未变化可跳过；失败不被误认为已完成；用户不手改生成资产（规则变化走新版本重生成）。
- **R5.5** 全局性错误**可以**中止整批运行。

### R6 资产形态

- **R6.1** 规范知识资产**必须**是可移植、可独立保存的文件资产。
- **R6.2** 索引与缓存**必须**可删除、可重新生成（它们不是规范资产）。
- **R6.3** 人和机器**必须**都是一级消费者（人直接可读、机器可程序化解析结构）。
- **R6.4** 基础知识资产**必须**与 Source 明确对应。
- **R6.5** 跨 Source 关系与检索结构**必须**属于可重建的衍生层。
- **R6.6** **必须**存在唯一规范数据源，其他表示由它派生。

### R7 成本

- **R7.1** 成本与耗时**必须**可观察、可比较、可控制。
- **R7.2** 系统**不得**为节省成本而静默降低可信要求。

## 验收条件

> 以下条件全部针对端到端接缝（见 Testing Decisions）以产品级断言验收，不依赖内部实现。

**A1 审计门**
构造含"引用不存在于原文的知识单元"的输入（用确定性 AI 替身注入），运行后：该单元**不出现**于可信发布集；缺口报告含"审计拒绝"条目并指向该单元。

**A2 推理审计**
构造"引用真实存在但断言超出引用支持范围"的单元，运行后：该单元不进入可信发布集，缺口报告记录拒绝原因。

**A3 对账完整性**
对任意一次运行（含被人为注入失败的 Source）：运行摘要覆盖**当前资产版本内的全量实体**——每个输入 Source 都有实体状态（成功/失败/待复核），每个知识单元都有实体状态（通过/拒绝/待复核/失败），合计与对账一致，无静默消失；本次运行实际处理的实体单独可辨（处理/跳过可区分，跳过以引用既有产出表达，不引入新状态值）。对账由运行摘要承载，缺口报告不含全量正常对账（只含异常与缺口）。

**A4 Source 级无拒绝**
Source 状态枚举为 成功/失败/待复核，不存在 Source 级"拒绝"；Source"成功"允许包含已拒绝但已记录的知识单元。

**A5 同版本幂等**
同一 Corpus、同一资产版本连续运行两次：第二次跳过未变化且已成功的 Source（在运行摘要中可辨，引用既有产出）；可信发布集与缺口报告内容不变（允许时间戳类运行元数据不同）；无新旧混杂。

**A6 输入变化检测**
修改一个 Source 的内容后重跑：仅该 Source 被重新处理，其余 Source 保持原产出。

**A7 阶段独立性**
人为使某关键处理步骤对某 Source 失败后：可**仅重跑该 Source 或该关键步骤**（两者均可独立触发，缺一即失败），不需全量重跑；失败结果不被跳过逻辑当作已完成。

**A8 资产可移植性**
将规范资产目录复制到另一空环境：人可直接阅读资产内容；程序可解析出结构（知识单元、来源引用、实体状态）且与解析工具无耦合；删除派生的索引/缓存后可重建，知识无损。

**A9 忠实层不可篡改 + Review Note 归属**
构造触发 Review Note 的输入（如"疑似口误"）：忠实层内容与原文一致，未被修改；Review Note 单独存在、标注为系统判断，且由审查环节产出（提炼阶段的自检疑点不得直接落为正式 Review Note）。

**A10 衍生层隔离**
删除/重算衍生层：基础层（按 Source 的资产）不受影响，可信发布集不变。V1 衍生层内容允许为空或最小（裁决 5），但边界与可重算性必须可验证。

**A11 缺口报告可读性**
缺口报告同时满足人可读与机器可解析（四类缺口类别齐全，含 Source、原因、下落）。

**A12 成本可观察与可控**
一次运行产出可比较的成本与耗时记录（至少：每次运行的总成本与耗时；足以在两次运行间比较），且存在可观察的成本控制手段（如可设定运行范围以控制开销——控制的具体机制是实现决策，可观察性是验收点）。成本与耗时记录是 Run Summary 的组成部分（物理文件是否分开是实现决策）。

**A13 噪声容忍**
输入含口头填充、重复、轻微转写错误的 Source：处理不失败；噪声不出现在知识单元中；正常知识照常提炼。

**A14 待复核语义**
构造"审计环节无法可靠判定通过或拒绝"的知识单元（替身返回不确定结论）：该单元实体状态为待复核（不进入可信发布集），运行摘要有其下落，且待复核有明确理由记录——不是因为"低质量"被兜底。

**A15 覆盖审计独立性**
构造"提炼替身自评覆盖良好、但覆盖审计（独立审查环节）判定遗漏重要知识"的输入：缺口报告出现"覆盖存疑"条目，且该判定来自审查环节而非提炼自评。

**A16 指标成对存在**
任意一次完整运行的产出同时包含可信性指标与知识覆盖指标（R4.5）；构造"提炼替身保守产出极少单元"的输入：覆盖指标反映其低覆盖（不得因通过率高而得分高）。

**A17 引用不变量**
构造"无有效 Source Reference 的知识单元"（替身产出无引用单元）：该单元不进入可信发布集，且在运行摘要/缺口报告中有显性下落（具体归入哪类 Gap Category 不作断言）。

**A18 分层结构与审计尺度分离**
一次正常运行后：资产同时含知识单元层与聚合层（要点/主题/概要）；聚合知识不携带单元级实体状态、不被计入单元级通过率指标。

**A19 中断恢复**
人为中断一次运行（如处理到部分 Source 时终止）：再次运行时已完成的中间结果被复用（不重复处理），未完成部分继续执行至完成；最终产出与无中断的完整运行等价（忽略运行元数据差异）。

**A20 版本可区分**
修改提炼或审计标准后重跑：新资产版本与旧版本可区分（可同时指认"这是哪一版标准的产物"），同版本内无新旧标准混杂。

**A21 唯一规范源**
对同一知识内容，规范数据源唯一；由它派生的其他表示（展示/索引/衍生结构）在删除后可由规范源重建，且重建不改变规范源本身；不存在"修改派生物而规范源不知情仍一致"的双向漂移通道。

**A22 降本不降门槛**
构造使完整审计成本较高的输入并以受限配置运行：可信发布集的准入判定与全量配置一致（审计策略可以不同——分层/风险驱动，但同一知识单元的准入结论不得因省钱而放宽；被降级处理的单元走待复核/缺口而非直接通过）。

## Implementation Decisions

> 本节记录规格层面已定的决策；凡是事实源明确"属于实现决策"的内容一律不在此固化，见文末 Open Implementation Decisions。

1. **产品不变量（Q27 裁决）**：阶段化运行和局部重算能力是产品要求，但任何具体的阶段拓扑（如 Parse / Extract / Audit / Assemble 四阶段）**不是**产品强制架构——四阶段仅作为当前参考管线模型保留。实现必须遵守的不变量：
   - 生成与审查的认知责任必须分离；
   - 关键处理步骤能够独立恢复或重算；
   - 发布集成员资格由可信审查结果决定（构建于哪个内部步骤属于实现决策）；
   - 失败或规则变化不要求整个 Corpus 无条件全量重做。
2. **审计门的语义**：可信发布集成员资格只由知识单元的审计结果（"通过"）决定；无有效 Source Reference 的知识单元同样不得进入（R2.4）（ADR-0003）。
3. **两正交分离维度的物理含义**：忠实层/审查层分离体现为"忠实层知识与 Review Note 分别存放且后者标注系统判断"；基础层/衍生层分离体现为"按 Source 的资产与跨 Source 衍生产物分别组织，衍生层可整体删除重算"（ADR-0002）。
4. **实体状态语义**：见 R4.6——Source 级 成功/失败/待复核（语义已定义），Knowledge Unit 级 通过/拒绝/待复核/失败；缺口报告四类是缺口类别（Gap Category），不是实体状态。不定义完整状态迁移图，"跳过"是运行行为不是状态。
5. **AI 环节的角色**：提炼（知识单元抽取、聚合、覆盖自检信号）与审计（推理审计、覆盖审计、Review Note 确认）由 AI 参与多个认知环节完成；忠实性审计含纯程序比对部分。覆盖的最终结论由审查环节产生，提炼自评只是信号（裁决 3、4）。AI 环节与管线其余部分解耦，且**按认知角色可独立替换**，使测试可对每个认知角色注入独立可控的确定性替身（见 Testing Decisions）。
6. **人机双读**：规范资产唯一（R6.6），其形态同时满足人直接可读与机器可解析；具体格式（及其派生关系方向）是实现决策。

## Testing Decisions

**唯一测试接缝：端到端管线（含运行请求）。** 输入 = 一个 Corpus（含受控构造的 Source 文件）+ 运行请求（全量 / 指定 Source / 指定关键步骤 / 受限成本配置）+ **按认知角色独立可控的确定性替身**（提炼替身与审查替身分别注入、分别设定行为）；输出 = 资产目录（可信发布集 + 缺口报告）+ 运行摘要（全量对账 + 成本与耗时记录）。所有验收条件（A1–A22）都在此接缝上以产品级断言验证，不测内部模块。

- **为什么替身按认知角色独立可控**：裁决 3/4 要求"覆盖结论由审查环节产生、Review Note 由审查环节产出"——只有一个整体替身时，最终产物无法区分结果来自生成还是审查。替身的角色分离是**测试输入的一部分**（对每个认知角色分别预设行为），断言仍然只针对外部产物；这不是窥探内部结构。
- **好测试的标准**：只断言外部可见行为（资产内容、状态、缺口、重跑语义），不断言内部结构（阶段划分的函数签名、中间产物格式、目录布局）——后者是实现决策，测试不得把它们锁死。
- **AI 环节的替身**：确定性假模型按认知角色（提炼 / 推理审计 / 覆盖审计）分别设定预置行为，包括故意注入"引用不存在""断言脑补""触发 Review Note""覆盖自评良好但审计判遗漏""审计不确定结论""无引用单元""保守极少产出"等场景，使审计门、对账、幂等、待复核、指标成对等行为可确定性地触发与断言。
- **Prior art**：绿地项目，无现有测试。本规格的验收条件即为测试清单的种子。
- **真实模型冒烟**：确定性替身之外保留一个可选的真实模型端到端冒烟测试（不进默认验收），用于验证真实 AI 环节的接线。

## Out of Scope（V1）

- ASR 语音识别；视频/音频下载；翻译；字幕时间轴编辑与人工字幕修复（事实源非目标 1–4）。
- 多用户、账号、权限、多租户。
- ASS 之外格式的完整支持（架构不得排除，验收不含）；无时间轴输入的验收（Q26：未来兼容约束，非 V1 交付）。
- 千集级规模的性能优化（设计不堵死，不预建机制）。
- 人工 override/annotation 机制与更重的版本管理体系（ADR-0004：本轮范围决定，非对未来架构的否决）。
- 被拒内容的隔离资产库（ADR-0003：物理存放方式是实现决策）。
- 检索/RAG 服务本身（资产可被检索消费，但 V1 不含检索系统）。
- Ticket 拆分（下一阶段）。

## 规格级裁决记录（原未决冲突与审查裁决，均已由用户裁决）

以下 6 点在规格起草时为未决项，已由用户于 2026-09-01 裁决并落入本规格正文与验收条件：

1. **待复核（Needs Review）的定义**：系统当前无法可靠判定该 Knowledge Unit 应通过还是拒绝，但存在足够理由需要人工或后续审查。它**不是**"低质量"的兜底状态，也不是一般警告。
2. **低可信项**：**不**新增为独立状态或独立领域术语。"低可信"只作为触发待复核或提高抽查优先级的**风险信号**。
3. **覆盖审计的位置**：正式的知识覆盖审计属于**独立审查环节**的职责。提炼阶段可以产生覆盖自检信号，但生成者自评不得作为最终覆盖结论。
4. **Review Note 的产生**：Review Note 属于**审查层产物**。提炼阶段可以发现疑点，但正式 Review Note 由审查环节确认并产出，以保持忠实层与审查层分离。
5. **衍生层 V1 交付程度**：V1 **不要求**完整实现跨 Source 的概念归并、关系推理、矛盾检测等衍生知识能力。V1 只要求基础层与衍生层**边界明确**、衍生层**可重算**原则被保留，避免未来被基础资产结构锁死。
6. **对账信息位置**：完整的 Source / Knowledge Unit 去向对账属于**运行摘要（Run Summary）**。缺口报告（Gap Report）只记录执行失败、审计拒绝、覆盖存疑、警告等异常或缺口，**不承担全量正常对账职责**。

以下 3 点在规格审查后由用户于 2026-09-01 裁决：

7. **无时间轴输入（Q26）**：V1 不把无时间轴输入纳入正式验收范围。保留产品级兼容原则：Source Reference 的概念不能把时间戳作为成立的必要条件；未来无时间轴 Source 应能通过其他定位方式获得 Source Reference。属于未来兼容约束，不是 V1 当前必须交付的输入能力。
8. **阶段拓扑不锁定（Q27）**："阶段化运行和局部重算能力"是产品要求，但 Parse / Extract / Audit / Assemble 四阶段不是产品强制架构，仅作为参考管线模型保留。产品不变量：生成与审查认知责任分离；关键步骤可独立恢复/重算；发布集成员资格由可信审查结果决定；失败或规则变化不要求全量无条件重做。发布集在哪个内部阶段构建属于实现决策。
9. **实体状态语义收紧（审查裁决）**：不定义完整状态迁移图，只定义可观察语义——Source 成功 = 流程完整结束且所有 Knowledge Unit 均有明确可解释下落（含被拒单元不妨碍成功）；Source 待复核 = 存在未获最终结论、需后续判断的问题；Source 失败 = 流程无法完整完成。拒绝/待复核/失败不得混用。

## Open Implementation Decisions

> 事实源明确留给实现阶段的 How。本清单是实现的自由空间：不选择其中任何一项不构成规格违反，但实现必须能支撑上述全部 MUST 与验收条件。

1. **CLI 命令设计**：命令数量、命名、参数形态（PRODUCT：运行形态）。
2. **输入变化识别机制**：哈希算法与比对粒度（ADR-0004）。
3. **资产版本标识**：版本字段形态、递增方式、存放位置（ADR-0004）。
4. **跳过判定机制**：四要素（输入未变 + 版本一致 + 阶段成功 + 产物有效）的具体校验方式（ADR-0004）。
5. **原子写入机制**：临时目录 + rename 或其他（ADR-0004）。
6. **中间产物与缓存策略**：落盘形态、生命周期、清理策略（PRODUCT：中间结果支持恢复；ADR-0003：被拒内容物理存放方式）。
7. **规范源格式选型**：人可读文件为主 + 结构内嵌、还是结构文件为主 + 可读派生，及其他文件形态（ADR-0005：验收条件是可移植、可独立保存、唯一规范源）。
8. **索引/缓存技术**：是否引入、用什么（ADR-0005：可删除、可重建即可）。
9. **审计策略组合**：全量 / 分层 / 风险驱动的具体组合（PRODUCT：成本原则——经真实数据验证后决定）。
10. **忠实性比对的算法**：精确匹配、规范化后匹配、模糊匹配的选用与容差（PRODUCT：可程序比对即可）。
11. **AI 模型选择与提示词设计**：提炼与审计的模型、提示词、结构化输出方式（ADR：是否不同模型不是产品要求）。
12. **AI 环节的替身接口**：确定性替身如何注入管线（本规格 Testing Decisions 要求可替换，具体机制是实现决策）。
13. **全局性错误的判定清单**：哪些错误属于全局性、中止的判定标准（ADR-0003）。
14. **Segment 划分算法**：语义分段的具体方法（CONTEXT：Segment 是引用锚定目标，划分方式未定）。
15. **知识单元 schema**：单元类型的字段定义、来源引用的数据结构（ADR-0001：审计规则如何按单元类型组织属于实现决策）。
16. **聚合知识的质量审查形式**：单独审查的具体形态（Q24：可单独接受质量审查，形式未定）。
17. **成本/耗时的记录与呈现**：记录粒度、比较方式（PRODUCT：可观察、可比较、可控制即可）。
18. **目标语言与运行时**：编程语言、依赖、运行环境（事实源未触及，完全开放）。
